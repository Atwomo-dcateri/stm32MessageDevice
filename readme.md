stm32驱动控制板，**负责执行机器人的指令**

## 功能说明

本工程运行在 STM32 下位机上，通过 `USART1` 与树莓派通信，负责：

- 接收树莓派下发的串口协议帧
- 解析控制指令并驱动 OLED、舵机等外设
- 采集 `MAX30102` 心率与血氧数据
- 按协议将健康数据主动上报给树莓派

当前代码中：

- `communication` 模块负责协议收发、解析、分发
- `servo` 模块负责舵机角度控制
- `oled` 模块负责屏幕显示
- `max30102` 模块负责心率和血氧采集与计算

## 串口协议

### 帧格式

所有通信帧统一采用如下格式：

```text
AA 55 | TYPE | LEN | DATA... | CRC_H CRC_L | BB
```

- 帧头：`0xAA 0x55`
- `TYPE`：帧类型
- `LEN`：数据段长度
- `DATA`：负载数据
- `CRC`：对 `TYPE + LEN + DATA` 计算的 `CRC16-CCITT`
- 帧尾：`0xBB`

### 帧类型

树莓派 -> STM32：

- `0x10`：OLED 控制
- `0x11`：舵机控制
- `0x12`：查询传感器
- `0x13`：参数配置

STM32 -> 树莓派：

- `0x01`：心率/血氧上报
- `0x03`：传感器状态上报
- `0x04`：ACK
- `0x05`：NAK

### OLED 指令

`TYPE = 0x10`

- 清屏：

```text
DATA = [0x02]
```

- 显示文本：

```text
DATA = [0x01, x, y, text_len, text_bytes...]
```

- 显示表情：

```text
DATA = [0x00, confidence, name_len, name_bytes...]
```

说明：

- `x`、`y` 为显示起始坐标
- 当前 OLED 适配层内部会把 `y` 换算成页地址

### 舵机指令

`TYPE = 0x11`

```text
DATA = [servo_id, angle, speed]
```

- `servo_id = 0x00`：当前已接入的舵机
- `angle`：`0 ~ 180`
- `speed`：当前接口预留，已接收但暂未参与控制

说明：

- 当前工程只实际支持 `servo_id = 0x00`
- 若发送 `servo_id = 0x01`，STM32 会返回 `NAK`

### 查询传感器

`TYPE = 0x12`

```text
DATA = []
```

STM32 收到后会立即回传一帧心率血氧数据，并返回 `ACK`。

### 参数配置

`TYPE = 0x13`

当前支持设置健康数据上报周期：

```text
DATA = [interval_ms(4字节，大端)]
```

例如设置为 `1000 ms`：

```text
00 00 03 E8
```

### 心率血氧上报

`TYPE = 0x01`

```text
DATA = [hr, hr_ok, spo2, spo2_ok]
```

- `hr`：心率
- `hr_ok`：心率是否有效，`0/1`
- `spo2`：血氧
- `spo2_ok`：血氧是否有效，`0/1`

### 传感器状态上报

`TYPE = 0x03`

```text
DATA = [status, err_code]
```

- `status = 1`：有有效数据
- `status = 2`：当前无有效数据或采集结果不可用

## 当前限制

- `MAX30102` 当前保持原有接口实现，通信模块通过适配层读取数据，没有重写其核心算法接口
- `MAX30102` 中断引脚尚未在 CubeMX 中完整建模，当前代码兼容为可轮询运行
- 舵机当前仅接入一个通道，协议中第二个舵机 ID 仍为预留
- OLED 当前文本显示走现有字符接口，长字符串未做自动换行管理
